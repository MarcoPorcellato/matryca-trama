# Contributing to Matryca Trama

Thank you for helping build a reliable, welcoming Logseq sidecar.

## Before opening a change

Read the README, the relevant documents under `docs/`, the security policy, the
contributor licensing policy, and the code of conduct. For a new capability,
explain the user problem, the Logseq OG/DB scope, the authority boundary, and
how the change remains useful in the Community foundation.

Keep pull requests small and focused. Documentation and contract changes should be complete, plain English, and consistent with the existing terminology. Do not add Pro source code, private Brain implementation details, vault data, credentials, generated caches, or speculative stack commitments.

## Pull requests

Describe what changed, why it matters, affected boundaries, tests or checks performed, and any known limitations. Add focused tests for behavior changes. Preserve Markdown authority, deterministic behavior, explicit write consent, and safe handling of untrusted vault content.

Maintainers may request an architectural decision record before accepting a cross-cutting change. A review approval does not grant permission to access private repositories, user vaults, or secrets.

## Licensing

Issues, research, design proposals, and review comments are welcome. Do not
submit material whose licence or provenance you cannot verify.

The project intends to offer both noncommercial Community rights and separate
commercial rights. A normal pull request statement is not enough to guarantee
that maintainers can grant both. Until a lawyer-reviewed contributor agreement
or equivalent relicensing grant is adopted, maintainers will not merge external
code or documentation contributions into the product tree. Read
[CONTRIBUTOR_LICENSING.md](CONTRIBUTOR_LICENSING.md) before opening a pull
request. This temporary gate protects contributors and the project; it is not a
claim that issue discussion transfers copyright.

## Questions

Use the public support channels described in [SUPPORT.md](SUPPORT.md). Security issues must follow [SECURITY.md](SECURITY.md).
